Part 1 - Brain

A three-tier learning stack that turns a Unitree Go1 into something that acts like a cat.

TL;DR

The cat-feel does not live in the locomotion layer and it does not live in the skill library. It lives in a small thing on top: a behavioral-mode attractor with a 6-dimensional mood latent and a stochastic decision period. Add those three to a vanilla PPO categorical head and a generic walker, and the rollout starts to look like a cat.

This page summarizes Part 1 — Brain. It also describes the substrate the brain runs on (Tier 1 walker, Tier 2 skills) and documents the paradigms we tried and threw away.

The stack

brain (Tier 3) — PPO + 6-D mood + 6-mode attractor, ~0.5 Hz ↓ skill ID skills (Tier 2) — { walk, crouch, lie_belly, stay } + scripted get_up ↓ velocity / joint targets motion (Tier 1) — Go1 velocity-tracking walker (mjlab PPO), 50 Hz ↓ joint torques MuJoCo + Unitree Go1

Each tier is independently trainable. The contribution of Part 1 is the brain layer plus the empirical observation that the skill set should be small — four learned skills is enough, more skills do not help.

Why three pieces, specifically

attractors A low-frequency mode-transition policy picks one of six behavioral modes (resting, observing, stalking, playing, grooming, exploring). Each mode exposes a coherent subset of skills via an action mask. Without this, the brain thrashes between skills every tick.

mood A 6-vector Ornstein–Uhlenbeck latent. Three of its dimensions, passed through a sigmoid, are the weights on the curiosity / comfort / play reward streams. Behavior shifts gradually rather than discretely — a sleepy cat takes minutes to become a playful one.

stochastic decision period The brain is consulted every T ~ U(1.5, 4.0) s, not on a fixed clock. This single change eliminates the metronomic 2 Hz switching pattern that a fixed-tick categorical head produces, without any retraining.

Skill library

Four learned skills, one scripted recovery. Earlier versions of the system carried fifteen named skills; we converged here after the faking-is-enough principle: scripted PD for postures, RL only where RL is necessary.

walkGo1 mjlab velocity-tracking walker.
crouchStable crouch posture, 489-step episode.
lie_bellyBelly-down loaf pose.
stayFreeze current joint config.
get_upScripted PD keyframe sequence (not RL).
brain (composed)10-min autonomous rollout.

How it works — algorithm details

The brain is three cooperating loops at different timescales: a slow mood latent that drifts over minutes, a mode-transition attractor that commits to behavioral modes over tens of seconds, and a fast PPO skill policy that picks among the active mode’s skills every 1.5–4 s. This section gives the exact numbers from the source.

1 · Mood latent — 6-dim Ornstein–Uhlenbeck process

A 6-element vector state ∈ [−1, 1]&sup6; drifts continuously. Once per sim step (dt = 0.05 s) Mood.update(dt) applies:

state ← state − θ · state · dt + σ · √dt · ε, ε ~ N(0, I&sub6;) clip(state, −1, 1) θ (mean-reversion rate) = decay_per_minute / 60 = 0.05 / 60 ≈ 8.3 × 10⊃⁻⁴ s⊃⁻¹ σ (noise per √s) = 0.02 τ (OU time constant) = 1 / θ ≈ 1 200 s ≈ 20 min

The six dimensions have fixed semantic roles:

IndexNameRole
0energy Biases PLAYING and EXPLORING mode logits when high
1alertness Biases OBSERVING and STALKING mode logits when high
2sociability General attractor bias; reserved for social-distance reward (v2)
3curiosity_w Reward weight: σ(2·state[3]) scales the curiosity stream
4comfort_w Reward weight: σ(2·state[4]) scales the comfort stream
5play_w Reward weight: σ(2·state[5]) scales the play stream

The sigmoid is σ(x) = 1 / (1 + e−2x), mapping the OU range [−1, 1] onto approximately [0.12, 0.88]. Dimensions 3–5 are the only ones read by the reward composer; dimensions 0–2 provide additional logit bias to the mode-transition softmax via _mode_bias_from_mood in attractor.py. At startup state ~ U(−0.1, 0.4), so the cat begins curious and energetic rather than inert.

2 · Behavioral attractor — 6 modes, mood-biased softmax

ModePolicy.tick(dt, mood) runs every step but only considers a mode transition when two gates are satisfied simultaneously: the cat has dwelled in the current mode for at least min_dwell_s = 8.0 s, and a decision-cadence timer of decision_period_s = 4.0 s has elapsed. When both fire, the next mode is sampled from:

logit(RESTING) = 1.0 · w_com logit(OBSERVING) = 0.5 · w_cur + 0.2 · w_play logit(STALKING) = 0.5 · w_cur + 0.6 · w_play logit(PLAYING) = 1.0 · w_play logit(GROOMING) = 0.3 · w_com logit(EXPLORING) = 1.0 · w_cur where (w_cur, w_com, w_play) = mood.weights() [each in (0, 1)] p(mode) = softmax(logit / T), T = 0.8 (transition_temperature)

If the sampled mode differs from the current one, time_in_mode resets to zero, restarting the minimum-dwell gate. This produces multi-minute behavioral episodes without explicit timers.

Each mode exposes a coherent subset of skills. The full per-mode allow-lists and hard-blocked skills are:

ModeAllowed skillsHard-blocked (ignores soft-pass)
RESTING lie_belly, crouch, get_up, staywalk
OBSERVING crouch, get_up, stay —
STALKING crouch, get_up, stay —
PLAYING walk, get_up —
GROOMING lie_belly, crouch, get_up, staywalk
EXPLORING walk, get_up —

soft-pass Out-of-mode actions are suppressed with probability 1 − mode_soft_pass = 0.70 and let through with probability mode_soft_pass = 0.30. Hard-blocked skills bypass the coin flip entirely — walk never fires in RESTING or GROOMING regardless of the policy output.

stochastic decision period The skill policy is not queried every sim step. After each skill selection the env draws a fresh commitment window T ~ U(decision_period_min_steps, decision_period_max_steps) × dt. In the 10-min rollout this was configured as 30–80 steps at dt = 0.05 s, giving T ~ U(1.5, 4.0) s. Within each window the previous skill repeats, so the robot commits to an action rather than thrashing at 20 Hz.

3 · PPO brain — observation, action space, and reward

Observation space: 15-dim flat vector (defined in curiosity_feat.py as CURIOSITY_OBS_DIM_V0 = 15).

SliceDimsContent
[0:6] 6Mood latent state[0..5]
[6:8] 2Cat world-frame XY position
[8:10] 2cos(yaw), sin(yaw) — avoids angle wrap
[10] 1Body height (m)
[11] 1Horizontal speed |v| (m/s)
[12] 1Time-in-skill clipped to 10 s, rescaled to [0, 1]
[13:15] 2Nearest play-target Δxy relative to cat (zeros if none)

Action space: Discrete(6). Index 0 is HOLD — dispatches stay (freeze current pose). Indices 1–5 map to walk, crouch, lie_belly, stay, get_up in skill-registry order.

Reward composition. Four streams are summed each step:

R = curiosity_w · w_cur · r_curiosity + comfort_w · w_com · r_comfort + play_w · w_play · r_play + hold_w · r_hold Base weights (CompositeRewardConfig): curiosity_w = 0.2, comfort_w = 0.4, play_w = 0.4, hold_w = 1.0 (hold_w is NOT mood-modulated — stillness is rewarded regardless of mood state)
StreamFormulaKey parameters
r_comfort 0.8 · gsoft(d) + 0.2 · gwarm(d)
g(d) = exp(−d² / 2σ²) 		σ = 1.0 m; soft = couch-tagged entities, warm = radiator-tagged entities
r_play Within paw_range = 1.5 m:
|v_ball| + 0.5 if a swat-class skill is active 		Ball speed in m/s; causal bonus on skill co-occurrence (cheapest-possible credit assignment)
r_curiosity ICM forward-model error:
η · ½ ‖φ̂(st+1) − φ(st+1)‖² 		η = 0.5; encoder / forward / inverse MLPs: feature_dim 64, hidden 128; inverse-loss weight β = 0.2 (Pathak 2017); Adam lr = 10⊃⁻³
r_hold +0.01 per step when cat is still and no moving play-target is within saliency range speed < 0.05 m/s; saliency radius 0.6 m; target-speed gate 0.05 m/s (motionless balls are not salient)

The ICM module is updated separately from PPO: after each rollout CuriosityUpdateCallback batches all (φt, a, φt+1) transitions from info[“curiosity_transition”] and runs one Adam step on L = (1 − β) · Lfwd + β · Linv. PPO sees only the scalar r_curiosity, never the encoder gradients.

PPO hyperparameters (Stable-Baselines3).

HyperparameterValueRationale
ent_coef0.05 Prevents collapse to a single skill. SB3 default (0.0) produces degenerate cat behavior — behavioral variability requires sustained entropy; do not decay.
clip_range0.2 SB3 default; tightening to 0.1 was unnecessary once ent_coef was set
learning_rate3 × 10−4 SB3 Adam default
n_steps64 Rollout horizon per policy update
n_epochs2 Reuse passes per rollout buffer
policyMlpPolicy Vanilla MLP — no CNN (v0 obs are vectors, not pixels)

What we tried and removed

A paper that only reports the final design overstates how obvious that design was. These paradigms were tried, integrated, and removed:

AMP imitation track. Trained PPO + a style discriminator over ~20 retargeted cat motion clips. Under velocity commands, the resulting policy moved zero meters in five seconds. We moved cat-feel up to Tier 3.
walk-these-ways as a unified skill space. Forked the mjlab Go2-Flat task into a MoB variant with body-height, gait-frequency, and stance commands. Two consecutive runs failed to actually expose the new commands to the policy. We use separate skill checkpoints.
Single-policy RL get-up. Eleven variants (v1–v10 plus FR-Net auxiliary head). Eight converged to sphynx or belly-flat reward-hacks. One looked successful but only because of a curriculum-at-deployment bug. The final get_up is a 400-tick scripted PD keyframe and works on the first try.

cd robot-pet-cat
python3.11 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"

# Run a 30-second autonomous rollout

    --duration 30 --output renders/demo.mp4
